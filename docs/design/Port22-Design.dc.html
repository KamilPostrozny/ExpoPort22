Port22 — mobile terminal design explorations
Context read from the codebase: SPEC.md, KeyBarView.swift, TabsView.swift, ContentView.swift, Theme.swift. The app already has a precise system: Catppuccin four-flavour theming through semantic roles (accent=blue, panel=mantle, scrim=crust…), JetBrains Mono Nerd Font everywhere, iOS 26 Liquid Glass bars whose geometry is measured off Safari (49pt circles, 35pt keys, 34pt edge margins), and a Safari-style zoom-into-card tab switcher over tmux windows.
Assumptions: Catppuccin-first on both platforms — Android keeps the brand and swaps only nav/gesture patterns (gesture pill, predictive back, container-transform, flush surfaces per Material 3 Expressive). Terminal screens shown in Mocha, setup in Latte (matching the repo screenshot); every colour is a theme role, never a one-off. Tabs are tmux windows driven over exec channels — nothing here invents client-side tabs.

8Edge handle, built — Claude Code first
8aLive in both prototypes. 7b won, so the ribbon row is gone from iOS and Android: no collapsed state, no swipe-to-dismiss setting, no reserved height. A 5px handle in the process colour breathes on the right edge at thumb height; tap or swipe it left to open, and the panel floats over output — the terminal never reflows. It closes on a cap tap, a terminal tap, a swipe right, or leaving the window. Open the claude window in the iOS prototype to try it; the slash caps print real command output into the scrollback.
CLAUDE CODE — THE STACK, BOTTOM UP
No panel container: the caps float as individual pills in a right-aligned vertical column, exactly as 7b drew them, with the handle sliver still at the foot of the stack. Because proximity to the thumb is the ranking, the column reads bottom-up — the most urgent action sits lowest, destructive caps sit highest, and every recipe follows the same rule.
NOW (bottom) — ⎋ stop interrupts the current turn, ⇧⇥ plan mode cycles the accept-edits modes, attach uploads from the phone and inserts the path. The three things you reach for mid-turn, first because they're time-critical.
COMMANDS — /plugins · /config · /usage · /model · /context · /clear. Each types the command and presses return in one tap; these are the ones that are pure navigation, where typing a slash on a phone keyboard is the whole cost. No label under them — the command IS the label.
SESSION (top) — ^C ^C quit, the one destructive cap, so it sits farthest from the thumb and alone. First tap prints (^C again to exit) and the cap re-reads tap again; it disarms itself after ~3s. Double-^C is the app's own contract, so the cap mirrors it rather than hiding it.
Group headers are 9.5px, right-aligned, unpilled, and carry a shadow so they stay legible straight over output; they only appear when a recipe has more than about five caps — vim and htop stay a flat stack. Caps grew to 40px (44 on Android) now that they're free-floating targets rather than items inside a padded box, and the column scrolls if a recipe outgrows the space above the keyboard.
8bWhich apps get a handle. The test for a cap: a keystroke that is hard to type on a phone (modifier chords, slashes, backslashes, function keys) and consequential — not a shortcut you already have a key for. Ten recipes ship in Settings → Input → Edge handle, each toggleable; unknown processes get no handle at all rather than a guessed one.

7dOne cap shape for everything, and what each approach costs.
ONE CAP, THREE INKS — 35px tall, glyph then label, always in a row
:wsave
attach
:q!force quit
The old ribbon mixed two cap builds — 52px stacked columns with 8.5px labels for keystrokes, and wider inline rows with 12.5px labels for icons and agent actions — so the same surface had two type scales and two silhouettes. Now: glyph (mono 14px, or a 12px icon) then label (12px system, sub ink), padding 0 12, radius 18, height 35 — identical to a key-bar key. Danger changes ink and fill tint only, never shape, and stays rightmost. No borders except on danger.
VERTICAL COST, KEYBOARD UP
today44–56px of the 214px of visible terminal — collapsed saves 12px, which is why it never felt like a state.
7a puck0px. Panel floats over output only while open.
7b handle0px, and no horizontal cost in the bar either.
7c takeover0px, no reveal tap — pays in displaced system keys.
The dot is the whole notification. Same six-colour process scale as before, pulsing only while a job actually runs. It is the only always-on pixel the ribbon gets — presence without a row.
Collapsed state is deleted. There are two states now, closed and open, and TUI recipes are no longer special-cased — everything arrives closed.
Open is transient. It closes on any cap tap, on a terminal tap, and on process exit. Nothing to dismiss permanently, so the swipe-to-dismiss setting and the "returns when the process changes" rule both go away.
Attach keeps its progress track — same cap shape, filled left-to-right, ✕ cancels. In 7a and 7b it holds the panel open until done.

6dThe rules this surface follows — so the sheet and the full view never drift apart.
Sheet vs. view. The sheet holds only what you change while connected — flavour, font size, tmux, disconnect. Anything you set once lives in the full view. Nothing appears in both except appearance, which the view shows read-only as a value row.
One level of depth. Three drill-ins only — Identity, Context ribbon, Key bar. Each is a list of the same rows, never a form. Back pops the sub-screen first, then the surface; on Android that is the system back and the predictive-back gesture.
Values are truth, not labels. Every row's right side shows the current value (id_ed25519, 6 on, 10 000 lines) so the screen reads as a session summary you could hand to someone.
Recipes are user-owned. Turning a recipe off removes that cap set from the ribbon permanently — the ribbon is the app's signature surface, so it has to be one someone can decline.
Destructive rows stay red and inert. Forget host key and Disconnect are text rows, not buttons, and both confirm — an accidental tap in Settings must never drop a session.
Platform split. iOS: grouped inset cards, chevrons, right-aligned values, Face ID row. Android: full-bleed rows, accent section headers, two-line items, M3 switches, and the foreground-service row. Same tree, same copy, same order.

Both prototypes carry it — ⋯ → Settings → All settings. Try next: "add a hosts list so Port22 opens on a picker" · "design the connection-failed and host-key-changed states" · "put per-host overrides on the terminal settings".

5dThe divergence list — everything that is not a straight port, so nothing gets decided twice in build.
Material — no backdrop blur anywhere (RenderEffect is 12+ and costly over a live terminal): every glass surface becomes surface-container #313244 with elevation. Corners 16dp buttons, 20dp clusters, 28dp sheets. Type is Roboto; the terminal stays JetBrains Mono.
Key bar — docks flush to Gboard (8dp sides, no bottom gap) and floats with 14dp margins when the keyboard is down. Same four keys, same divider, same arrows button.
Keyboard — Gboard is the IME, so Port22 owns only the strip above it. The suggestion row shows shell history instead of words; the bar re-measures on IME resize (voice, one-handed, floating).
Back — predictive back is wired at every level: sheet → dismiss, browser → up one directory, then dismiss, switcher → back to the pane, terminal → home. iOS has edge-swipe on none of these.
Nav modes — gesture nav is drawn here. On 3-button nav the system bar is 48dp instead of 24dp: the floating bar's bottom margin drops to 6dp and the docked state is unchanged, so nothing else moves.
Clipboard — a bottom sheet, not a popover, and it takes the whole width. Long-press Paste still opens it.
Switcher — FAB replaces the plus button, Done is a text button, and the open/close is a container transform rather than the Safari-style zoom.
Upload — same destination browser, Material chrome, and a snackbar with UNDO on save. UNDO deletes the just-written file over the same SFTP channel.
Background jobs — a foreground-service notification carries the run: process name, elapsed time, and Stop / Background actions matching the ribbon's caps. iOS can only offer this while the app is alive.
Ribbon — identical behaviour on both, including collapsed TUI recipes and the dot colour scale; only the container material differs.
